# 20 线索与跟进 SOP（跨平台统一）

目标：让“多平台获客”不变成多人多表的混乱状态；任何线索都可追踪、可复盘。

## 1. 线索记录（必做）

- [ ] **建立线索台账**（产出物：复制 `templates/线索台账.md` 并开始使用）
  - 验收：每条咨询都有记录；至少包含平台、车型、意向项目、当前状态
- [ ] **定义状态流转**（产出物：状态列表写入台账顶部）
  - 建议：新线索 → 已回复 → 已报价/已给方案 → 已预约 → 已到店 → 已成交 → 已评价 → 复购/转介绍
  - 验收：每条线索必须处于某个状态，不允许“空状态”
- [ ] **归因规则统一**（产出物：归因说明）
  - 规则：以“首次接触平台”为主；如二次触达来自其他平台，在备注里记录
  - 验收：复盘时能按平台统计“咨询→到店→成交”

## 2. 响应与跟进节奏（必做，时限见 `config.md`）

- [ ] **首响 SLA**（`FIRST_RESPONSE_SLA`）
  - 动作：收到私信/评论/电话 → 先确认车型与诉求 → 给出下一步（预约或到店评估）
  - 验收：随机抽查最近线索，均满足 SLA 或有原因记录
- [ ] **未到店二次触达**（`FOLLOW_UP_SLA_NO_SHOW`）
  - 动作：针对“已报价/已给方案但未预约”的线索，发送一次关键信息补充（案例/注意事项/可选时间）
  - 验收：触达内容不含违规留资与夸大承诺
- [ ] **到店后评价引导**（`REVIEW_REQUEST_SLA`）
  - 动作：施工完成 → 明确质保/注意事项 → 引导平台评价（按平台路径）
  - 验收：评价引导不出现诱导违规表述（按平台规则）

## 3. 报价与方案输出（必做）

- [ ] **报价前信息采集最小集合**（产出物：一条采集话术）
  - 车型/车龄（或玻璃面积/车况）、预算、使用场景、是否有旧膜/旧车衣、期望效果
  - 验收：没有这些信息不做“拍脑袋固定价”，避免纠纷
- [ ] **方案给出方式统一**（产出物：方案模板）
  - 结构：你的诉求复述 → 推荐方案（含包含内容与边界）→ 预计时长 → 预约建议 → 质保口径
  - 验收：方案内容可被复用到各平台笔记/团购详情

## 4. 合规留资与沟通边界（必做）

- [ ] **留资策略**（写入 `LEAD_CAPTURE_POLICY` 并执行）
  - 优先：平台内私信、电话组件、平台表单/预约（如有）
  - 需要外部留资时：以平台规则为准，避免在公开内容里直接引导
- [ ] **效果与承诺边界**（写入 `CLAIM_BOUNDARY` 并执行）
  - 不做绝对化承诺；不贬低竞品；不使用不可验证对比

## 5. 评价与差评处理（必做，尤其大众点评/抖音本地生活）

- [ ] **好评引导话术**（产出物：一条话术 + 触发时机）
  - 验收：不出现违规诱导（例如“返钱换好评”等）
- [ ] **差评处理流程**（产出物：处理模板）
  - 时限：按平台规则与 `FIRST_RESPONSE_SLA` 的同等紧急程度处理
  - 步骤：确认事实 → 公开回复（简洁）→ 私下沟通（平台内）→ 记录原因 → 形成改进项
